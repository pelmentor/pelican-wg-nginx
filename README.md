# WG-Nginx: WireGuard + Nginx + PHP-FPM + Admin Panel

Standalone Docker image with WireGuard VPN client, Nginx web server, PHP 8.1 FPM, a Go WebSocket server for real-time log streaming, and a two-area admin panel with multi-user accounts. Designed for Unraid but works on any Docker host.

## Features

- **Nginx + PHP 8.1 FPM** (curl, gd, mbstring, zip, xml, opcache extensions)
- **WireGuard VPN client** (optional -- leave keys empty for a plain web server)
- **PresharedKey support** for additional WG encryption
- **Two-area web interface:**
  - **Client area** (`:7890`, blue) -- serves user content from `/data/user/webroot/`
  - **Admin area** (`:9876`, red, `/admin/*`) -- full management panel
- **Admin panel pages:**
  - **Dashboard** -- CPU, memory, disk, network stats + service status
  - **Console** -- xterm.js terminal with real-time WebSocket log streaming + command input
  - **File Manager** -- browse, upload, download, edit, create, delete, rename, copy, compress, decompress, chmod, search
  - **Settings** -- edit WG/Nginx/PHP configs, restart services
  - **Users** -- manage accounts (admin only)
  - **Logs** -- admin activity log viewer (admin only)
- **Multi-user accounts** with three roles (admin, operator, viewer)
- **Real-time WebSocket console** (Go binary, streams logs via Nginx proxy)
- **Security:** CSRF protection, rate limiting, session timeout, security headers, Zip Slip protection, path traversal prevention
- **Activity logging** with toast notifications
- **Log rotation** at startup (files >10MB truncated)
- **Healthcheck** built into the image (`/api/health`)
- **Trivy vulnerability scanning** in CI pipeline
- **Auto-migration** from v2.0 flat `/data` layout to v3.0 structure

## Quick Start

```bash
docker run -d \
  --name wg-nginx \
  --cap-add=NET_ADMIN \
  --restart unless-stopped \
  -p 7890:7890 \
  -p 9876:9876 \
  -v /path/to/data:/data \
  ghcr.io/pelmentor/wg-nginx:latest
```

Then open `http://YOUR_IP:9876` and log in with the credentials from `docker logs wg-nginx`.

On first run, a default `admin` account is created with an auto-generated password. Change it after first login.

## Ports

| Port | Purpose |
|------|---------|
| `7890` (TCP) | Client area -- user web content (Nginx) |
| `9876` (TCP) | Admin area -- management panel |
| `6790` (TCP, internal) | WebSocket server (Go, not exposed) |
| WG_LISTEN_PORT (UDP) | WireGuard (if configured) |

## Two-Area Layout

**Client area** (port 7890, blue theme) serves static and PHP content from `/data/user/webroot/`. This is what end users see -- your website, app, or service.

**Admin area** (port 9876, red theme) is the management panel. Only authenticated users with valid accounts can access it. All admin routes go through the PHP front controller at `/app/admin/public/index.php`.

The two areas run on separate Nginx server blocks with separate access/error logs. The admin area includes security headers (X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer) and blocks direct access to PHP source files.

## Account System

Three roles with hierarchical permissions:

| Role | Capabilities |
|------|-------------|
| **admin** | Full access. Manage users, view logs, all file/console/settings operations. |
| **operator** | Dashboard, console (read+write), files (read+write+delete), settings (view), logs, activity. |
| **viewer** | Dashboard (read-only), console (read-only), files (read-only), activity. |

Default account created on first run: `admin` / `<auto-generated password>`.

Admins can create, edit, and delete user accounts from the Users page (`/admin/users`).

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `USER_PORT` | `7890` | Port for client area (user web content) |
| `ADMIN_PORT` | `9876` | Port for admin area |
| `ADMIN_PASSWORD` | auto-generated | Password for the default admin account (first run only) |
| `WG_PRIVATE_KEY` | empty | WireGuard private key (leave empty to disable WG) |
| `WG_ADDRESS` | `10.0.0.2/24` | Container IP in the WG network |
| `WG_PEER_PUBLIC_KEY` | empty | Peer public key |
| `WG_PEER_ENDPOINT` | empty | Peer address (host:port) |
| `WG_PEER_ALLOWED_IPS` | `10.0.0.0/24` | IPs routed through the tunnel |
| `WG_PRESHARED_KEY` | empty | Optional preshared key |
| `WG_LISTEN_PORT` | empty | WG listen port (if acting as server) |

## Data Volume

Mount `/data` to persist everything. The volume is split into two areas:

```
/data/
├── user/                     — service consumer data
│   ├── webroot/              — website files (served on :7890)
│   ├── config/               — generated nginx/php/wg configs
│   │   ├── nginx-site.conf
│   │   ├── php-fpm.conf
│   │   └── wg0.conf
│   ├── logs/                 — user-facing service logs
│   │   ├── nginx-access.log
│   │   ├── nginx-error.log
│   │   ├── php-fpm-error.log
│   │   └── wireguard.log
│   └── tmp/                  — runtime (PID, socket, nginx temp)
│       ├── nginx.pid
│       ├── php-fpm.sock
│       └── nginx/
└── admin/                    — panel owner data
    ├── users.json            — user accounts (bcrypt hashes)
    ├── .admin_password       — auto-generated password (hidden from file manager)
    ├── nginx/                — admin nginx configs
    │   ├── nginx.conf
    │   └── admin.conf
    ├── logs/                 — admin panel logs
    │   ├── admin-access.log
    │   ├── admin-error.log
    │   └── activity.json
    ├── sessions/             — PHP session files
    └── ratelimit/            — rate limiter state files
```

## Console Commands

Type these in the admin panel Console page:

| Command | Description |
|---------|-------------|
| `help` | Show available commands |
| `status` | Show all service statuses |
| `wg show` | WireGuard interface status |
| `wg peers` | Peer details (endpoints, handshakes, transfer) |
| `ping <host>` | Ping a host (e.g. `ping 10.0.0.1`) |
| `nginx reload` | Reload Nginx config (tests first) |
| `nginx test` | Test Nginx config for errors |
| `logs access` | Last 30 lines of access log |
| `logs error` | Last 30 lines of error log |
| `phpinfo` | PHP version and extensions |
| `clear` | Clear the terminal screen |

All commands are whitelisted -- no arbitrary shell execution.

## Security Features

- **CSRF protection** -- per-session tokens verified on all POST requests (body field or header)
- **Rate limiting** -- file-based limiter with configurable windows per key (login, API)
- **Session timeout** -- 30-minute inactivity timeout, session ID regeneration on login
- **Security headers** -- X-Frame-Options DENY, X-Content-Type-Options nosniff, Referrer-Policy no-referrer
- **Path traversal prevention** -- `realpath()` + prefix check on all file operations
- **Zip Slip protection** -- all archive entries validated before extraction
- **Filename sanitization** -- uploaded files stripped of special characters
- **Bcrypt password hashing** -- cost factor 12
- **Whitelisted console commands** -- no shell injection possible
- **Separate ports** -- admin panel isolated from user content
- **www-data process isolation** -- Nginx workers and PHP-FPM run as unprivileged user
- **Trivy scanning** -- CI pipeline scans for CRITICAL/HIGH vulnerabilities

## Testing & Update Cycle

```bash
# Pull and run
docker pull ghcr.io/pelmentor/wg-nginx:latest
docker run -d --name wg-nginx --cap-add=NET_ADMIN \
  --restart unless-stopped \
  -p 7890:7890 -p 9876:9876 \
  -v /mnt/user/appdata/wg-nginx:/data \
  ghcr.io/pelmentor/wg-nginx:latest

# Get admin credentials (first run only)
docker logs wg-nginx

# Debug
docker logs wg-nginx --tail 50
docker exec -it wg-nginx bash

# Update to new version
docker stop wg-nginx && docker rm wg-nginx
docker pull ghcr.io/pelmentor/wg-nginx:latest
# then docker run again (same command as above)

# Full cleanup (removes everything including data)
docker stop wg-nginx && docker rm wg-nginx
docker rmi ghcr.io/pelmentor/wg-nginx:latest
rm -rf /mnt/user/appdata/wg-nginx
```

> **Note:** Data in `/mnt/user/appdata/wg-nginx` survives `docker rm`. Only deleting that folder is a full reset.

## Unraid Setup

1. Go to Docker tab, click Add Container
2. Repository: `ghcr.io/pelmentor/wg-nginx:latest`
3. Add ports: `7890` (TCP), `9876` (TCP)
4. Add path: `/data` mapped to `/mnt/user/appdata/wg-nginx`
5. Extra parameters: `--cap-add=NET_ADMIN`
6. Optional: add WG env vars if you need VPN
